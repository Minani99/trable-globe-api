## 2. 상품 완성도 (이번 PR)

**내 여행(허브)**
- `김여행님의 여행` 인사와 요약 카드 4개: 다가오는 여행 · 여행 중 · 기록 전 · 다녀온 나라.
- 여행마다 단계별 색 배지(계획 중 파랑, 여행 중 주황, 기록 전 노랑, 다녀온 여행 초록)를 붙였습니다. 계획은 `D-14`, 여행 중이면 `2/3일차`로 표시합니다.
- 다음 여행 카드에 출발까지 남은 날 또는 여행 몇 일차인지 크게 표시합니다.
- **흐름 수정:** 끝났지만 공개하지 않은 여행은 `기록 전`으로 표시하고 누르면 기록 마무리 화면으로 바로 갑니다. 전에는 일반 편집기로 열려 허브의 "여행 기록하기"와 동작이 달랐습니다.

**랜딩**
- 기능 소개 문구를 키우고, 끝에 어두운 마무리 배너("다음 여행부터 지구본에 남겨 보세요")와 주요 버튼을 추가했습니다.

**공유 페이지(전환)**
- 로그인하지 않은 방문자에게 공개 프로필과 여행 상세 끝에 "내 지구본 만들기" 배너를 보여 줍니다. 가입 후에는 보던 페이지로 돌아옵니다.
- 이전·다음 여행이 하나뿐이면 카드를 가로 전체로 펼칩니다.

**모바일**
- 여행 중 빠른 기록 버튼을 일정 화면과 여행 만들기 폼에서는 숨깁니다. 입력칸과 하단 버튼을 가리던 문제입니다.
- 스크롤과 포커스 이동이 고정 하단 메뉴 아래로 숨지 않도록 `scroll-padding`을 넣었습니다. 버튼이 메뉴에 가려 눌리지 않던 문제입니다.

**공통**
- 주요 버튼과 카드에 그림자, 호버 시 떠오르는 효과를 줬습니다. 통계 숫자와 섹션 제목을 강조했습니다.

## 3. 배포 안정성

- 앱 전역 `error.tsx`를 추가했습니다. 설정·로그인·공유 링크·랜딩에서 예상하지 못한 오류가 나도 레이아웃을 유지하고 "다시 시도/홈으로"를 보여 줍니다.
- Vercel 운영 빌드에 `API_BASE_URL`이 없으면 빌드 로그에 경고를 남깁니다. 전에는 조용히 localhost로 요청해 실패했습니다.

## 운영자가 직접 확인할 것

1. **Render `DB_IDLE_TIMEOUT_MS`:** 대시보드에 `60000`이 있으면 지우거나 `240000`으로 바꾸세요. 지난 배포의 커넥션 유지 개선이 이 값에 막힙니다.
2. **Vercel 함수 리전:** Render 서비스와 같은 리전으로 맞추세요(Vercel 프로젝트 → Settings → Functions → Region).
   - Render 기본 리전은 Oregon이고, 이 경우 Vercel은 `pdx1`(Portland)이 맞습니다.
   - 로그인 화면은 매번 Vercel → Render를 왕복하므로 리전 차이가 그대로 지연이 됩니다.
   - 실제 Render 리전을 이 환경에서 확인할 수 없어 코드로는 바꾸지 않았습니다.
3. **콜드 스타트:** 무료 Render 인스턴스는 0.1 CPU라 JVM 기동에 수십 초가 걸립니다.
   - 근본 해결은 유료 플랜입니다.
   - Java 클래스 데이터 공유(CDS) 아카이브를 Docker 이미지에 넣으면 기동이 빨라질 수 있습니다. 다만 이 환경에 Docker가 없어 검증하지 못했기 때문에 Dockerfile은 바꾸지 않았습니다.
