# 기존 기능 안정화 · 2026-10-30

새 기능 추가보다 기존 기능의 오류·성능·모바일 사용성 검증을 우선한다.
자동 검사 통과를 모든 기기에서 완벽하게 동작한다는 의미로 사용하지 않는다.

## 이번 수정과 회귀 검증

- 예약 재연결: 오프라인을 거친 뒤 새 응답이 오기 전에는 이전 예약을 표시하지 않는다.
  지연 응답을 둔 실제 브라우저 오프라인/온라인 전환으로 확인한다.
- 조회 취소: 예약 화면 이탈·새로고침과 메인 화면의 연속 갱신에서 불필요해진 조회를 취소한다.
  이전 응답이나 취소 오류가 최신 화면을 덮어쓰지 않도록 한다.
- API 응답: 성공 여부의 타입과 데이터 필드를 검사한다. 조회의 빈 데이터는 오류로,
  삭제의 정상적인 null 데이터는 성공으로 처리한다. 오류 요청 번호는 유지한다.
- 예산 초과: 예상 비용이 예산의 250%면 문구도 250%로 표시한다. 막대 너비만 100%로 제한한다.
- 준비물 저장: HTTP 성공이어도 갱신된 목록 데이터가 null이면 성공으로 처리하지 않는다.
  입력과 필터를 유지하고 재시도할 수 있도록 하며, 실패한 완료 체크는 되돌린다.

## 완료 판단에 필요한 근거

- 수정한 오류를 재현하는 단위/브라우저 검사와 전체 CI가 통과해야 한다.
- 운영 배포의 `/api/version`이 병합 커밋과 일치해야 한다.
- 기존 기능 전체의 사용자 체감 속도 개선은 실제 기기의 측정 없이 완료로 표시하지 않는다.
  로그인, 지구본 탐색, 계획 저장, 장소 검색, 지도 이동, 사진 업로드를 각각 측정한다.
- 실제 iOS Safari·Android 브라우저의 키보드, 터치, 설치형 실행, 네트워크 전환은 별도 확인한다.
- 운영 메일 수신·DB 복구·지도 공급자 설정은 [베타 체크리스트](beta-checklist.md)의 미확인 상태를 유지한다.

다음 작업도 새 기능 추가보다 이 검증의 빈 부분과 재현된 문제 해결을 우선한다.
