# Travel Globe UI/UX 점검 — 2026-11-12

## 점검 방법

- 로컬 백엔드(H2) + 프론트엔드 프로덕션 빌드(`next build && next start`)로 실행했습니다.
- 테스트 계정 1개를 만들었습니다. 공개 여행 3건(일본·프랑스·태국, 사진 없음)과 비공개 계획 1건(제주)을 넣었습니다.
- 페이지 16개를 데스크톱(1440×900)과 모바일(iPhone 13, 390×844)에서, 로그인 전·후로 나눠 전체 화면을 캡처했습니다.
- 각 페이지에서 가로 넘침, 이름 없는 컨트롤, 라벨 없는 입력, 12px 미만 글자, 32px 미만 터치 영역, h1 유무, 콘솔 오류를 자동으로 측정했습니다.
- 한계: 이 샌드박스는 외부 네트워크(Open‑Meteo, 지도 타일)가 막혀 있습니다. 그래서 날씨·지도는 실패 상태로만 확인했습니다. 실제 기기 키보드와 다크 모드는 이번 범위에서 제외했습니다.

## 총평

기본기는 탄탄합니다. 측정한 모든 화면에서 가로 넘침이 0이었고, 이름 없는 버튼과 라벨 없는 입력도 거의 없었습니다(`외부 이미지 주소` 입력 1건만 예외). 하단 탭바, 단계형 계획 생성, 여행 중 화면의 하단 액션바도 모바일 패턴에 잘 맞습니다.

반면 아래 세 가지는 첫인상과 신뢰도를 떨어뜨립니다.

1. **사진 없는 여행이 "깨진 이미지"처럼 보입니다.**
2. **모바일 첫 화면에서 핵심 행동(가입, 지구본)이 접힘선 아래로 밀립니다.**
3. **한글에 자간과 숫자 0 채움("01", "00")이 들어가 대시보드처럼 기계적으로 읽힙니다.**

## 잘 된 점 (유지 권장)

- 모든 측정 화면에서 가로 스크롤이 없고, 320~1440px 대응이 안정적입니다.
- 폼 라벨, 버튼 이름, 단일 h1 구조를 대부분 지켰습니다.
- 계획 생성 3단계, 여행 중 하단 액션바(일정 편집·사진·메모), "다음 단계" 안내 카드처럼 진행 방향을 알려 주는 흐름이 명확합니다.
- 스튜디오 목록의 지도형 플레이스홀더는 사진이 없어도 품질감이 유지됩니다. P1‑1의 기준으로 삼으면 좋습니다.

## 권장 진행 순서

1. P1‑1, 2: 플레이스홀더 통일과 모바일 랜딩 CTA. 체감 효과가 가장 크고 변경 범위가 작습니다.
2. P2‑5, 6: 자간·0 채움 정리와 아바타 이니셜. CSS와 유틸 하나씩 바꾸면 됩니다.
3. P3‑11~14: 문구와 접근성 세부. e2e 문구 검사(`launch-ux`, `travel-journey` 등)를 함께 갱신해야 합니다.
4. 나머지는 베타 사용성 테스트 결과를 보고 판단합니다.
