# 비공개 베타 체크리스트

첫 베타는 5~10명이 각자 실제 여행 한 건을 기록해 보는 범위로 운영합니다. 소셜 기능이나
앱 전환보다 기록을 만들고 다시 찾는 흐름이 끊기지 않는지를 먼저 확인합니다.

## 초대 전 필수 조건

- [ ] Render가 `prod` 프로필과 전용 Neon DB를 사용한다.
- [ ] Vercel의 `API_BASE_URL`과 Render의 `CORS_ALLOWED_ORIGINS`, `PUBLIC_SITE_URL`이 실제 주소와 일치한다.
- [ ] Resend 발신 도메인이 인증됐고 실제 이메일로 인증·재설정 링크가 도착한다.
- [ ] Cloudflare R2 운영 버킷과 CORS가 설정됐고 사진 업로드·삭제가 동작한다.
- [ ] 모바일 브라우저에서 홈 화면 설치가 가능하고, 설치 후 `/studio`가 독립 창으로 열린다.
- [ ] 비행기 모드에서 새 페이지를 열면 오프라인 안내가 표시되고 다른 사용자의 비공개 화면은 캐시에 남지 않는다.
- [ ] 종료된 비공개 계획의 `기록 완성하기`에서 장소·대표 사진·짧은 기록을 확인하고 공개 상세로 이동한다.
- [ ] Neon 보존 기간을 확인하고 [`operations.md`](./operations.md)의 복구 리허설을 한 번 완료했다.
- [ ] GitHub의 수동 Production smoke가 통과한다. 운영 주소를 바꾼 경우에만 `PRODUCTION_SITE_URL`, `PRODUCTION_API_URL` 변수를 덮어쓴다.
- [ ] Vercel의 `MAPTILER_API_KEY`를 설정하고 MapTiler 키의 허용 출처를 Production·Preview 도메인으로 제한한다.
- [ ] Vercel Firewall에 `POST /api/auth/*`를 IP 기준으로 제한하는 규칙을 먼저 Log 모드로 적용한 뒤 차단 기준을 확정한다.
- [ ] 운영자에게 Vercel, Render, Neon, Resend, R2 및 GitHub Actions 장애 알림이 도착한다.

## 한 사람이 확인할 핵심 여정

1. 새 계정을 만들고 이메일을 인증한다.
2. 로그아웃한 뒤 다시 로그인하고, 비밀번호 재설정 메일도 한 번 확인한다.
3. 여행 제목·기간을 입력하고 한국어 자동완성으로 세 장소를 추가한 뒤 전체화면 지도에서 핀 하나를 조정한다.
4. 총예산·비용·예약을 추가한 뒤 내용을 수정하고 결제·확정 상태를 바꾼다.
5. 장소 순서를 바꾸고 각 장소에 사진을 연결한다.
6. 작성 도중 페이지를 벗어났다가 돌아와 임시 저장 내용을 복구한다.
7. 여행 종료 상태에서 `기록으로 완성할 여행`을 열고 실제 장소를 확인해 공개 기록으로 전환한다.
8. 다른 브라우저나 로그아웃 상태에서 공개 지구본과 상세 화면을 확인한다.
9. 모바일에서 지구본 회전·확대와 장소 선택 전체화면 지도의 이동·확대가 페이지 스크롤과 서로 방해하지 않는지 확인한다.
10. 여행을 수정한 뒤 사진 한 장과 장소 한 곳을 삭제하고 결과가 즉시 반영되는지 확인한다.
11. 테스트가 끝난 계정은 설정에서 탈퇴하고 공개 주소가 사라졌는지 확인한다.

## 지원 기기 기준

처음에는 모든 기기를 완벽하게 지원하려 하지 않고 다음 조합을 출시 기준으로 둡니다.

| 구분 | 최소 확인 조합 |
| --- | --- |
| iOS | 현재 및 직전 주요 iOS의 Safari, 390px 안팎 화면 |
| Android | Chrome 또는 Samsung Internet, 360px·412px 화면 |
| Desktop | 최신 Chrome·Edge·Safari, 1280px 이상 |
| 접근성 | 키보드만으로 가입·작성 가능, 모션 감소 설정, 200% 확대 |

가로 스크롤, 버튼이 화면 밖으로 나가는 문제, 지도가 페이지 스크롤을 계속 가로채는 문제는
베타 초대 전에 막습니다. 구형 WebGL 미지원 기기는 깨진 캔버스 대신 대체 국가 목록을 보여야 합니다.

## 피드백 분류

| 우선순위 | 기준 | 대응 |
| --- | --- | --- |
| P0 | 로그인 불가, 다른 사람의 비공개 기록 노출, 데이터 손실 | 즉시 베타 중단 및 복구 |
| P1 | 저장·수정·사진 업로드 실패, 모바일 핵심 화면 사용 불가 | 다음 초대 전 수정 |
| P2 | 정렬, 문구, 애니메이션, 특정 기기 레이아웃 불편 | 주간 디자인 묶음으로 수정 |
| P3 | 소셜·통계·앱 등 새 기능 제안 | 기록 흐름 안정화 이후 검토 |

친구는 사이트 하단의 `베타 의견`에서 양식을 복사해 초대받은 메신저로 보냅니다. 저장소에
접근할 수 있는 운영자는 GitHub의 `비공개 베타 피드백` 이슈로 옮겨 관리합니다. P0·P1에는
재현 기기, 발생 시각, 공개 가능한 경우 `X-Request-ID`를 남기고 이메일·비밀번호·인증 토큰은
절대 첨부하지 않습니다.

## 코드에 반영된 베타 안전장치

- 가입 화면과 모든 페이지 하단에서 베타 이용·개인정보 안내를 확인할 수 있습니다.
- 인증·설정·스튜디오·API 화면은 검색 노출을 차단하고 민감 응답은 브라우저에 저장하지 않습니다.
- 계정 탈퇴 성공 후 여행 사진과 프로필 사진을 R2 저장소에서도 삭제합니다.
- 전체 화면에 클릭재킹·MIME 스니핑 방지와 최소 권한 보안 헤더를 적용합니다.
- 브라우저 여정은 두 샤드로 나눠 워크플로의 대기·실행 시간을 줄입니다.

## 베타 종료 기준

- 서로 다른 사용자 5명 이상이 도움 없이 여행 한 건을 공개할 수 있다.
- 2주 동안 P0가 없고, 열린 P1이 없다.
- 작성 복구 성공률과 사진 업로드 성공률을 수동 기록으로라도 확인할 수 있다.
- 한 차례 DB 복구 리허설과 한 차례 잘못된 배포 롤백을 완료한다.
- 다음 개발 묶음은 피드백의 반복 빈도를 기준으로 결정한다.
